你是一名独立游戏开发者。

请从零制作一款可以在电脑浏览器中直接运行的 2D 俯视角恐怖逃生游戏。

游戏参考经典“后室”和阈限空间的氛围，但不要复制任何商业游戏的具体地图、角色、Logo 或受版权保护的素材。

请自主完成需求拆解、项目搭建、素材准备、编码、运行、浏览器试玩和问题修复。

不要只交付设计文档、静态页面或无法实际游玩的视觉 Demo。

最终结果必须具备完整的开始、探索、收集、追逐、解谜、失败和通关流程。

### 一、技术与项目要求

1. 使用 HTML、CSS 和 JavaScript 制作，核心游戏画面使用 Canvas 2D 渲染。
2. 画面必须是纯 2D 俯视角，不使用 Three.js、WebGL 3D 场景、伪 3D 透视走廊或预渲染 3D 视频。
3. 可以使用轻量级 2D 库，但不得为了简单效果引入体积庞大的游戏引擎。
4. 项目必须保存在当前工作目录中，并提供清晰的文件结构。
5. 必须包含可以直接打开的 `index.html`，或提供一条明确、可执行的本地启动命令。
6. 页面加载后不能出现控制台报错、资源 404、白屏或持续卡死。
7. 游戏应在 1440×900 和 1920×1080 分辨率下正常显示，画面不能被裁掉。
8. 保持代码可读，地图生成、玩家状态、敌人逻辑、物品系统和 UI 尽量拆分为独立模块。

### 二、美术与氛围

1. 整体视觉采用昏黄、旧绿色和灰褐色。
2. 场景需要包含重复墙纸、潮湿地毯、狭窄走廊、空房间、荧光灯和少量特殊区域。
3. 普通房间需要保持相似感，但不能完全复制粘贴，要通过墙纸污渍、灯光明暗、杂物或房间结构制造细微差异。
4. 增加轻微噪点、暗角、灯光闪烁和画面扰动，强化阈限空间的压迫感。
5. 敌对实体使用原创黑色剪影或抽象怪物形象，不直接使用其他后室游戏中的知名怪物造型。
6. HUD 尽量克制，不能做成颜色鲜艳的传统手游界面。
7. 开始页面应包含游戏名称、“开始游戏”“操作说明”“音效开关”三个入口。

### 三、外部素材规则

1. 允许使用外部图片、纹理、字体和音效。
2. 只能使用允许再利用的公开素材，优先选择 CC0、Public Domain、MIT 或其他许可清晰的资源。
3. 不要通过远程 URL 热链素材，需将使用的文件下载到项目内的 `assets` 文件夹，保证离线或网络波动时仍能运行。
4. 在项目根目录创建 `SOURCES.md`，记录每项外部素材的名称、原始地址、作者和许可类型。
5. 如果无法找到许可明确的素材，请使用 Canvas、CSS 或 Web Audio API 自行生成，不要使用来源不明的资源。

### 四、地图生成

1. 每次点击“新游戏”时随机生成一张新地图。
2. 地图建议采用网格结构，规模不得低于 35×35 个基础单元。
3. 地图至少包含普通房间、狭长走廊、录像室、密码终端区、出口区和一个不会刷出敌人的缓冲区域。
4. 房间和走廊布局必须真正变化，不能只更换道具位置或背景颜色。
5. 地图生成后必须进行连通性检查，玩家出生点、三盘录像带、密码终端和最终出口之间必须存在可行路径。
6. 三盘录像带不能生成在墙体、出口外部或玩家无法抵达的位置。
7. 敌对实体不能与玩家重叠出生，也不能直接出现在出生点附近。
8. 在界面角落显示本局地图 Seed。
9. 使用相同 Seed 时应能复现相同地图，方便测试和问题定位。
10. 普通模式不提供完整小地图，只允许玩家通过已经走过的路线、房间标识和环境细节辨认方向。

### 五、玩家操作

1. 支持 `WASD` 和方向键移动。
2. 按住 `Shift` 冲刺。
3. 按 `E` 与录像带、密码终端、出口和安全区域交互。
4. 按 `Esc` 暂停，并可继续游戏、重新开始或返回主菜单。
5. 移动必须有墙体碰撞，玩家不能穿墙或卡进障碍物。
6. 镜头平滑跟随玩家，不能产生明显抖动。
7. 玩家移动、冲刺、受惊和受伤需要有清楚但不过度的视觉或声音反馈。

### 六、核心任务流程

游戏目标是收集三盘录像带，获得密码线索，解锁出口并逃离当前楼层。

具体流程如下：

1. 玩家进入游戏后，HUD 显示当前目标“寻找第一盘录像带”。
2. 三盘录像带分别散落在不同区域，每盘录像带都包含一个数字和对应顺序。
3. 玩家拾取录像带后，屏幕短暂显示内容摘要，并把数字线索记录在任务栏中。
4. 收齐三盘录像带后，当前目标更新为“前往密码终端”。
5. 玩家在密码终端输入三位密码。
6. 密码错误时给出明确反馈，但不能直接清空已经收集的录像带。
7. 密码正确后，出口从锁定状态变为可开启状态，并在环境中给出方向提示。
8. 玩家到达出口并完成交互后进入成功结算页面。
9. 成功页面显示用时、移动距离、冲刺次数、被实体发现次数和当前 Seed。
10. 玩家可以选择使用相同 Seed 重玩，或生成新地图重新开始。

### 七、体力与理智系统

1. 玩家拥有体力值和理智值，两项数值都在 HUD 中显示。
2. 冲刺持续消耗体力，停止冲刺后逐渐恢复。
3. 体力耗尽时只能正常行走，并需要等待恢复后才能再次冲刺。
4. 长时间停留在黑暗区域、距离实体过近或被实体追踪时，理智值下降。
5. 进入明亮区域并暂时脱离危险后，理智值缓慢恢复。
6. 理智值较低时，加入轻微视野收缩、画面噪点、虚假脚步声或短暂幻影。
7. 低理智效果不能遮住全部视野，也不能让游戏失去可操作性。
8. 理智值归零时进入失败页面，并明确显示失败原因。

### 八、敌对实体逻辑

敌对实体至少包含以下状态：

1. 游荡：在可行走区域中随机移动，不长时间卡在墙角。
2. 怀疑：听到玩家奔跑、连续撞墙或近距离交互产生的声音后，前往声源附近调查。
3. 发现：玩家进入实体视野且中间没有墙体遮挡时，实体开始追逐。
4. 追逐：实体沿可行路径接近玩家，速度略高于玩家普通移动速度，但低于玩家满体力冲刺速度。
5. 丢失：实体失去视线后前往玩家最后出现的位置搜索，经过一段时间再回到游荡状态。
6. 攻击：实体与玩家发生接触后触发失败，不能隔墙攻击。

还需要满足以下要求：

1. 视线判断必须考虑墙体遮挡。
2. 声音范围与玩家行为有关，普通行走声音小，冲刺声音大。
3. 实体需要使用寻路或合理的网格移动逻辑，不能无视墙体直线穿越。
4. 玩家需要有机会通过关闭冲刺、绕路或进入缓冲区域摆脱追击。
5. 不要让实体一直守在密码终端或出口前，导致游戏无法完成。

### 九、声音设计

1. 增加持续但克制的荧光灯电流声和环境低频噪声。
2. 玩家行走与冲刺应使用不同节奏的脚步声。
3. 实体接近、发现玩家和进入追逐状态时，声音需要明显变化。
4. 拾取录像带、密码正确、密码错误、出口开启和游戏失败需要独立音效反馈。
5. 必须提供音效开关和音量调节。
6. 浏览器限制自动播放时，应在用户点击“开始游戏”后再初始化音频。

### 十、界面与信息反馈

游戏 HUD 至少显示：

1. 录像带收集进度 `0/3`。
2. 当前任务目标。
3. 体力值。
4. 理智值。
5. 当前 Seed。
6. 游戏用时。
7. 音效状态。

同时满足以下要求：

1. 可交互物体靠近后出现简短提示，例如“按 E 拾取录像带”。
2. 被实体发现时，用声音、边缘红光或短提示明确反馈。
3. 出口未解锁时说明还缺少什么条件。
4. UI 文字不能与背景融在一起，也不能挡住玩家周围的主要视野。

### 十一、失败与重新开始

以下情况触发失败：

1. 被实体接触。
2. 理智值归零。

失败页面需要显示：

1. 失败原因。
2. 本局存活时间。
3. 已收集录像带数量。
4. 使用相同 Seed 重新开始。
5. 生成新地图重新开始。
6. 返回主菜单。

重新开始后必须重置玩家位置、实体状态、任务进度、体力值、理智值和计时器，不能残留上一局状态。

### 十二、调试与验收功能

1. 增加仅在 URL 带有 `?debug=1` 时出现的调试面板。
2. 调试面板可以显示地图连通性、玩家坐标、实体状态、实体寻路路线、物品坐标和当前 Seed。
3. 普通模式不能显示这些调试信息。
4. 完成后至少使用三个不同 Seed 各测试一次地图连通性。
5. 至少完整试玩并通关一局。
6. 主动检查录像带能否全部获得、密码能否提交、出口能否打开、实体能否正常追逐、失败后能否重开。
7. 检查所有按钮、键盘操作和音量控制是否有效。
8. 检查浏览器控制台，修复可以复现的报错和资源加载问题。

### 十三、最终交付内容

完成后请提供：

1. 可运行的完整项目。
2. `README.md`，说明启动方式、操作方法、游戏目标和文件结构。
3. `SOURCES.md`，记录全部外部素材来源和许可。
4. `TEST_REPORT.md`，记录测试过的 Seed、完整通关结果、发现的问题和已经完成的修复。
5. 在浏览器中实际打开游戏，展示开始页面、探索过程、实体追逐、密码终端和成功结算页面。
6. 最后用简洁语言汇报实际完成情况、仍可继续优化的地方，以及启动游戏的方法。

不要在没有实际运行和试玩的情况下直接宣布任务完成。

如果某项功能受当前环境限制无法实现，请保留其余可用功能，并在最终汇报中明确说明原因，不要用静态假界面代替。
